# 三映CSV → 勘太郎CSV 変換アプリ（印刷勘太郎 連携）

三映様から届く印刷予定表CSV（**CSV-A**）を固定ルールで解釈し、人が確認・修正したうえで、印刷勘太郎の取込形式（**CSV-B・35列 A〜AI**）を **1案件1ファイル** で出力するWebアプリです。**AIは使いません**（変換はすべてルールベース）。出力したCSVは画面からダウンロードし、勘太郎側がパソコンに設置した**指定フォルダ**へ入れて取り込みます（CSV-Bの取り込みは確認済み）。

## 処理フロー

```
三映CSV（CSV-A：Shift_JIS/UTF-8、複数可）
   │  ① アップロード
   ▼
固定ルールで変換（sanei_config.yaml）
   ・本番/校正セクション分割、「裏」行の除外、受注№ごとに1案件へまとめる
   ・品名連結、用紙/印刷サイズ変換、色数の表裏分解、営業日で納品日計算、備考文面
   │  ② 画面で人が確認・修正（案件ごとに35列を表示。判断に迷う箇所は警告）
   ▼
案件ごとにCSV-B生成（1行目=全35列、2行目以降=N〜AB列のみ）
   │  ③ .tmpに書き切ってから rename（アトミック書込）
   ▼
連携フォルダ /data/incoming/ に 20260827_2603797-00-00_本番.csv …
   │  ④ 最後に .done ファイルを作成（書き終わりの合図）
   ▼
画面の「まとめてダウンロード」で保存 → 勘太郎の指定フォルダへ → 印刷勘太郎が取込
（ブラウザの保存先を指定フォルダにしておくと、ダウンロードするだけで入る）
```

## セットアップ

```bash
pip install -r requirements.txt
export APP_USERNAME=... APP_PASSWORD=... SECRET_KEY=...   # ログイン用
python -m app.main
# → http://localhost:8000 をブラウザで開く
```

変換ロジックだけを手元で試す場合（三映CSVは顧客情報を含むためリポジトリには入れない）:

```bash
python tools/run_sanei_demo.py path/to/CSV-A.csv --out ./out
python tests/test_sanei_converter.py   # 合成データでの単体テスト
python tests/test_samples.py           # 架空サンプルA〜Dの出力が期待どおりか（下記）
```

### 自動テスト（GitHub Actions）

GitHubに納める（プッシュする）たびに、`.github/workflows/tests.yml` が上の2つのテストを自動で実行します。
`tests/samples/` の架空サンプルA〜D（実データではない）を変換し、`tests/expected/` の正解CSVと1バイトずつ比べます。
Geminiに頼んだ修正で変換結果が変わってしまったら、ここが赤く（失敗に）なって気づけます。

- 変換ルールをわざと変えたとき（例: 変換表に寸法を足した）は、結果が変わるのが正しいので正解CSVを作り直します:
  GitHubの **Actions** タブ →「テストの正解を作り直す」→ **Run workflow**（手元なら `python tests/test_samples.py --update`）。
  作り直した正解はコミットされるので、変わったCSVの差分を目で確認してください。

## 「印刷勘太郎から求むものリスト」との対応表

| リストの項目 | 本アプリでの実装 | 勘太郎側と決めること |
|---|---|---|
| 1. SFTP接続情報 | 使わない（勘太郎側がパソコンに指定フォルダを設置済み）。SFTP送信の機能は `config.yaml` の `sftp.push_enabled` に残してあり、今は無効 | — |
| 2. CSVフォーマット | `sanei_config.yaml` の `output`（UTF-8・**BOM付き**・最小囲み・CRLF）と `csv_b_columns`（35列）。コード変更不要 | CSV-Bの取り込みは確認済み（岩崎様）。BOM付き・セル内改行（`cell_newline`）は、このアプリの出力そのもので確認しておく |
| 3. 命名規則 | `{下版予定日}_{受注№}_{本番/校正}.csv`（`sanei_config.yaml` の `filename_pattern`）。同名がある場合は上書きせず `_2` を付与 | 正式な命名規則の合意 |
| 3. 配置先 | アプリ内は `config.yaml` の `output.dir`（既定 `data/incoming/`）。勘太郎へは画面からダウンロードして指定フォルダへ | 誰がいつ入れるか |
| 3. 処理済みファイルの扱い | `archive/` `failed/` フォルダを用意。UIで3フォルダの状況を可視化 | 勘太郎側が取込後に削除するか移動するか |
| .doneトリガーファイル | CSVを完全に書き切った**後**に `.done` を作成（アプリ内の連携フォルダ）。ダウンロードするのはCSVだけ | 指定フォルダでは不要か確認 |
| 不完全CSVの防止 | `.tmp` に書いて `os.replace()` でrename（アトミック）。PUSH時もリモートで rename | — |
| 発生頻度 | 画面で確定した都度、その案件数ぶんのファイルを出力 | 取込タイミング |
| SSH鍵認証（SFTPを使う場合のみ） | パスワード不使用。Ed25519秘密鍵ファイルを参照（コードにハードコードしない） | 公開鍵の登録 |
| 固定IPアドレス制限（SFTPを使う場合のみ） | ネットワーク側の設定事項。アプリサーバーのIPを固定し、勘太郎側FWで許可リスト化 | 許可IPの登録 |

## 運用上の設計判断

- **変換は固定ルール、確定は人**: AIを使わず、同じ入力なら必ず同じ結果になります。変換表にない寸法・「裏」だけの案件・未定義の文面などは握りつぶさず画面に警告として出し、人が確認してから出力します。
- **列は見出し名で探す**: 三映CSVの列は位置ではなく見出し行の名前（順・受注№・寸法…）で探すため、列が増えたり並びが変わったりしても正しく読めます。必要な列が無いファイルは、取り違えたまま変換せずエラーにします（見出しの表記ゆれは `sanei_config.yaml` の `header_names` に追加）。
- **1案件1ファイル・全件検証してから書込**: 1件でも出力できない案件があれば1ファイルも書き出しません。出力後は確認画面を閉じ、同じ案件の二重出力（＝勘太郎への二重登録）を防ぎます。
- **ルールはすべて設定ファイル**: 固定値・変換表・備考文面・会社休業日・35列の定義は `sanei_config.yaml`。国民の祝日は `jpholiday` が毎年自動で判定します（年ごとの一覧の手入力は不要）。仕様変更はコードを触らずに反映できます（GAS版へ移す際はスプレッドシートへ転記）。
- **ログ**: すべての受付・変換・出力を `app.log` に記録します（いつ・どのファイル・何案件）。
- **Excelで中身を確認するとき**: CSV-BはBOM付きUTF-8なので、ダブルクリックで開いても文字化けしません。ただしExcelは開くときに自動変換するため、得意先コード `00332` が `332` に、日付が `#######`（列幅不足）に見えることがあります。ファイル自体は正しい値です。変換させずに見るには「データ → テキストまたはCSVから」で開き、列を「文字列」にしてください。
- **保存先の注意**: Renderの無料プランではディスクが再起動で消えます。出力したらすぐ「まとめてダウンロード」で回収してください。
- **セキュリティ**: ログイン必須、SFTPは鍵認証、出力ファイル名とダウンロードAPIはパストラバーサル対策済み。

## ファイル構成

```
printpro2/
├── sanei_config.yaml   # 変換ルール・CSV-B 35列の定義・出力形式（コード変更不要）
├── config.yaml         # 出力フォルダ・.done・SFTP・サーバー設定
├── requirements.txt
├── app/
│   ├── main.py            # FastAPI（API + 画面配信）
│   ├── sanei_converter.py # 三映CSV → CSV-B 変換エンジン（ルールベース）
│   └── csv_writer.py      # アトミック書込・.done
├── static/index.html   # 画面（アップロード→案件ごとの確認→出力→フォルダ状況）
├── static/login.html   # ログイン画面
├── tools/run_sanei_demo.py      # 変換のデモ実行
├── tests/
│   ├── test_sanei_converter.py  # 合成データでの単体テスト
│   ├── test_samples.py          # 架空サンプルA〜Dを変換し、正解CSVと比較
│   ├── samples/                 # 架空サンプル（実データではない）
│   └── expected/                # 正解CSV
├── .github/workflows/tests.yml  # プッシュのたびにテストを自動実行
└── data/
    ├── uploads/   # アップロードされた三映CSVの保管（監査用）
    ├── incoming/  # 出力したCSV（画面からダウンロード）
    ├── archive/   # 取込済
    └── failed/    # エラー退避
```
